<objective>
Levar o Correlation-ID pelo order-service inteiro: o filtro HTTP põe o `X-Correlation-Id` no MDC, o
`OutboxWriter` grava o valor numa coluna nova na mesma transação, o `OutboxRelay` o envia como message
attribute SQS `correlationId`, o `ReservationResultListener` o lê de volta para o MDC, o
`SagaTimeoutJob` herda o ID gravado no pedido e o `RestClient` o repassa ao catalog/auth.

Purpose: QUAL-02 no serviço que orquestra a saga — sem este elo o ID morre no Gateway. As colunas
`orders.correlation_id` e `outbox_event.correlation_id` (D-94, D-95) são decisões `costly` já tomadas
pelo usuário; não há checkpoint de decisão.

Output: pacote `observability` (`CorrelationContext`, `CorrelationIdFilter`), migração V4, outbox com
coluna e atributo, listener e timeout com MDC, interceptor do `RestClient`, testes unitários e ITs com
Postgres e LocalStack reais.
</objective>

## Decisões do planejador (Claude's Discretion) registradas por este plano

- `CORRELATION_CODE_PLACEMENT=duplicated-per-service` — `CorrelationContext` + `CorrelationIdFilter`
  copiados em cada serviço (pacote `observability`), sem módulo `common`: um módulo novo exigiria
  editar os 6 Dockerfiles (`dependency:go-offline` copia os poms) e o reactor; o projeto já duplica o
  outbox por decisão (D-62). Vai para o ADR 0011 (07-06).
- `SQS_CORRELATION_ATTRIBUTE=correlationId` (DataType String), enviado por `MessageBuilder.setHeader`
  + `SqsOperations.send(queue, Message)` e lido por `@Header(name = "correlationId", required = false)`
  — o `SqsHeaderMapper` 3.4.2 mapeia header ↔ atributo com o mesmo nome.
- `TRANSITION_CORRELATION_SOURCE=request-id` — `/approve`, `/ship`, `/deliver` usam o ID da própria
  requisição (nenhum código extra); só fluxos sem HTTP (`SagaTimeoutJob`) herdam `orders.correlation_id`.
- `LEGACY_CORRELATION=null` — colunas nullable, sem backfill; linha de outbox sem ID publica SEM
  atributo; o relay gera um ID só para a sua linha de log.
- `ORDER_CORRELATION_SETTER=recordCorrelationId` — método novo em `Order` chamado por `OrderService`
  logo depois de `Order.create`, para não mudar a assinatura usada por `OrderDomainTest`.
