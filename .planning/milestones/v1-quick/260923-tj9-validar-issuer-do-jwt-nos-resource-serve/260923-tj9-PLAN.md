## Por que esta abordagem (regra do projeto: explicar antes de usar)

A abordagem escolhida é a propriedade padrão do Boot `spring.security.oauth2.resourceserver.jwt.issuer-uri`, ao lado do `jwk-set-uri` que já existe. É o padrão documentado na referência do Spring Security para "JWK Set URI direto + validar o iss". Na produção, basta uma linha de YAML por serviço, sem Java novo e sem tocar no `SecurityConfig`.

Alternativa rejeitada: um bean `JwtDecoder` próprio no `SecurityConfig` (a sugestão do WR-07). Ele duplicaria o que o Boot já faz, colidiria com o bean de teste e, principalmente, manteria o teste substituindo o decoder de produção. A classe de falha que o WR-07 aponta continuaria possível.

Nos testes, o decoder deixa de ser trocado. Um `JwkSetUriJwtDecoderBuilderCustomizer` troca só a fonte de chave (do JWKS remoto para a chave pública em memória). Algoritmo, validadores padrão e validador de emissor continuam vindo da configuração de produção. É isso que faz o teste de `iss` errado provar alguma coisa.
