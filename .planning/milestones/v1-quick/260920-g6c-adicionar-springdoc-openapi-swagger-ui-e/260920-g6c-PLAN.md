Fatos verificados nesta sessão de planejamento — o executor NÃO precisa re-pesquisar:

- **Versão**: `org.springdoc:springdoc-openapi-starter-webmvc-ui:2.9.1` é o topo da linha 2.x no
  Maven Central (a linha 3.x existe mas é para Spring Boot 4.0 — fora da stack deste projeto, que
  está em Boot 3.5.16). O release 2.9.1 declara explicitamente "Upgrade Spring Boot to version
  3.5.16", exatamente a `${spring-boot.version}` do pom raiz. Use 2.9.1, não 2.8.5 (valor antigo
  citado em `01-RESEARCH.md`, hoje 12 patches desatualizado).
- **springdoc NÃO tem propriedades `springdoc.info.*`** — verificado contra springdoc.org/properties.html.
  Os prefixos reais são `springdoc.api-docs.*`, `springdoc.swagger-ui.*`, `springdoc.packages-to-scan`,
  `springdoc.paths-to-match`, `springdoc.show-actuator`, `springdoc.cache.*`. Título e descrição
  precisam vir de um bean `OpenAPI` (ou da anotação `@OpenAPIDefinition`). Por isso este plano usa
  chaves `orderflow.openapi.title` / `orderflow.openapi.description` no `application.yml` (namespace
  próprio do projeto, mesmo padrão do `orderflow.auth.token-ttl-seconds` que já existe no
  `auth-service/src/main/resources/application.yml`) injetadas no bean via `@Value`.
- **Caminhos servidos pelo springdoc** (defaults, mantidos): `/swagger-ui.html` (redirect 302 para
  `/swagger-ui/index.html`), `/swagger-ui/**` (recursos da UI), `/v3/api-docs` (o spec JSON) e
  `/v3/api-docs/**` (inclui `/v3/api-docs/swagger-config`, que a UI busca no boot).
- **Legitimidade do pacote**: o gate automático de legitimidade cobre apenas npm/pypi/crates —
  não existe verificação automática para o Maven Central neste ambiente. `01-RESEARCH.md` já contém
  a auditoria manual desta exata coordenada: `org.springdoc:springdoc-openapi-starter-webmvc-ui`,
  projeto com 5+ anos, alto volume de downloads, repositório público em github.com/springdoc/springdoc-openapi,
  **status Approved**. Nenhum checkpoint humano de legitimidade é necessário — a auditoria já foi feita
  e aprovada; este plano apenas atualiza o patch dentro da mesma linha major/minor auditada.
- **Gateway**: `gateway/src/main/resources/application.yml` aplica `StripPrefix=1`, então
  `/api/products/**` no gateway chega como `/products/**` no catalog-service. A Swagger UI servida na
  porta direta do serviço documenta os caminhos **sem** o prefixo `/api` — isso é correto e esperado;
  o README precisa dizer isso para não confundir quem comparar com a seção de endpoints do gateway.
