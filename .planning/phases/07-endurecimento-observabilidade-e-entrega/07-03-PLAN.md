## Phase Goal

Goal do ROADMAP (literal): "Deixar o projeto apresentável e verificável por um avaliador externo —
documentação OpenAPI de cada serviço, …". Este plano entrega o critério 1 para catalog e auth. (Goal
fora do formato de user story; nenhuma história inventada.)

Sequência: sem LocalStack (só Postgres Testcontainers); roda na onda 1 em paralelo com 07-01
(gateway) e 07-02 (order-service), sem módulo em comum.

## Decisões do planejador (Claude's Discretion) registradas por este plano

- `OPENAPI_SERVER_URL=/api` relativo, configurável por `orderflow.openapi.server-url` (env
  `ORDERFLOW_OPENAPI_SERVER_URL`). Honra D-90 (o Try it out vai pelo Gateway com o prefixo `/api` e
  `StripPrefix=1`); troca a URL absoluta do exemplo do D-90 por relativa para não dar erro de CORS
  quando a UI é aberta por `127.0.0.1`. Efeito aceito: o Try it out pela Swagger UI da porta direta do
  serviço deixa de funcionar — a UI canônica é a do Gateway. Confirmação no UAT (07-11).
- `ERROR_SCHEMA=ErrorResponse` por serviço em `config`, record só de documentação (os handlers seguem
  devolvendo `Map`, sem mudança de comportamento).
- `PUBLIC_OPERATION_MARK` — `POST /auth/login` recebe `@SecurityRequirements` vazio para anular o
  requisito global de `bearerAuth` só nessa operação.
- `JWKS_IN_SPEC=hidden` — `JwksController` com `@Hidden`: o Gateway não roteia `/.well-known/**`; o
  endpoint segue existindo para os resource servers.
- Tags em português: `Produtos`, `Autenticação`, `Empresas`.
